# 文件存储主键优化说明

## 优化目标

将文件存储表 `z_file` 的主键从雪花算法生成的数字 ID 改为包含完整路径信息的字符串 KEY，简化文件访问逻辑。

## 主要改动

### 1. 数据库表结构变更

**旧结构：**
```sql
CREATE TABLE z_file (
    id            NUMERIC(28)   NOT NULL PRIMARY KEY,  -- 雪花算法ID
    original_name VARCHAR(512)  NOT NULL,
    extension     VARCHAR(128)  NOT NULL,              -- 文件后缀
    file_size     BIGINT        NOT NULL,
    content_type  VARCHAR(128)  NOT NULL,
    usage         VARCHAR(255)  NOT NULL
);
```

**新结构：**
```sql
CREATE TABLE z_file (
    id            VARCHAR(512)  NOT NULL PRIMARY KEY,  -- 格式: yyyyMM/雪花ID(去除yyyyMM).后缀
    original_name VARCHAR(512)  NOT NULL,
    file_size     BIGINT        NOT NULL,
    content_type  VARCHAR(128)  NOT NULL,
    create_id     NUMERIC(28),                         -- 新增：创建人ID
    usage         VARCHAR(255)  NOT NULL
);
-- 移除了 extension 字段，后缀信息已包含在主键中
```

### 2. 主键格式说明

**格式规则：** `yyyyMM/雪花ID(去除yyyyMM).后缀`

**示例：**
- 雪花ID: `202512161030451234567890`
- 文件后缀: `png`
- 主键: `202512/161030451234567890.png`

**优势：**
1. **自动分片**：按月份（yyyyMM）自动分文件夹，便于管理
2. **直接访问**：主键即 OSS Key，无需拼接
3. **减少字段**：移除 extension 字段，简化数据结构
4. **清晰直观**：从主键即可看出文件存储路径

### 3. 代码变更

#### 3.1 实体类 `ZFile.java`
- 主键类型从 `BigDecimal` 改为 `String`
- 移除 `extension` 字段
- 新增 `createId` 字段

#### 3.2 服务类 `ZFileService.java`
- `buildFileKey()` 方法：生成格式为 `yyyyMM/去除yyyyMM的ID.后缀` 的 KEY
- `upload()` 方法：主键直接存储 fileKey
- `delete()` 方法：参数类型改为 `String fileKey`
- 移除 `getUrlById()` 方法，改为 `getUrlByKey()`

#### 3.3 DTO `OssPutRet.java`
- 移除 `extension` 字段
- 新增 `key` 字段，返回完整的 OSS Key

#### 3.4 控制器 `ZFileController.java`
- 所有 ID 参数类型从 `BigDecimal` 改为 `String fileKey`

### 4. 文件存储示例

**上传流程：**
```java
// 1. 生成雪花ID: 202512161030451234567890
BigDecimal snowflakeId = snowflakePrimaryKeyGenerator.getPrimaryKey();

// 2. 构建 fileKey: 202512/161030451234567890.png
String fileKey = buildFileKey(snowflakeId, "png");

// 3. 上传到 OSS (Key: 202512/161030451234567890.png)
ossService.upload(file, fileKey);

// 4. 数据库记录
ZFile zFile = new ZFile()
    .setId("202512/161030451234567890.png")  // 主键直接存储完整路径
    .setOriginalName("avatar.png")
    .setFileSize(12345L)
    .setContentType("image/png");
```

**访问流程：**
```java
// 直接使用主键生成访问URL
String fileKey = "202512/161030451234567890.png";
String url = ossService.getPublicUrl(fileKey);
// 结果: http://oss.example.com/bucket-name/202512/161030451234567890.png
```

### 6. 迁移步骤

如果需要从旧结构迁移到新结构：

1. **备份数据**
   ```sql
   CREATE TABLE z_file_backup AS SELECT * FROM z_file;
   ```

2. **删除旧表，创建新表**
   ```sql
   DROP TABLE z_file CASCADE;
   -- 执行新的建表语句
   ```

3. **重新上传文件**（推荐）
   - 由于主键格式变化，建议重新上传文件
   - 旧的 OSS 文件可以保留或清理

4. **数据迁移**（可选，复杂）
   - 需要解析旧的雪花ID，构建新的 fileKey
   - 在 OSS 中移动文件到新的路径
   - 更新数据库记录

### 7. 注意事项

1. **主键长度**：VARCHAR(512) 足够存储路径信息
2. **索引**：在 `usage` 和 `content_type` 字段上建立索引
3. **文件后缀**：确保上传时提取正确的文件后缀
4. **删除操作**：删除数据库记录的同时要删除 OSS 文件

### 8. 兼容性

- ✅ 新代码完全兼容新表结构
- ❌ 旧数据需要迁移或重新上传
- ✅ API 接口保持一致（参数类型从 BigDecimal 改为 String）

## 总结

通过将主键改为包含完整路径的字符串，实现了：
1. **简化代码**：减少字段和拼接逻辑
2. **提高性能**：主键即路径，无需额外查询
3. **便于管理**：按月分文件夹，清晰直观
4. **易于扩展**：可灵活调整路径格式
